# Секреты и границы защиты

Не публикуйте PostgreSQL password, API URI с паролем, Access Key/Secret Key,
MinIO root credentials, пароль Kopia repository, kubeconfig и дампы.
`work/`, `.env`, `*.credentials`, `reports/runs/` и бинарные CLI исключены из Git.
Публичные манифесты используют secretKeyRef; секреты генерируются при bootstrap и передаются kubectl через stdin.
Нельзя считать `gitignore` защитой уже добавленных файлов: перед push проверьте `git ls-files` и историю.

Kubernetes Secret содержит base64, а не самостоятельное шифрование. Secret приложения входит в копию
Kubernetes-объектов Velero. Поэтому доступ к бакету практически означает доступ к данным приложения.
Kopia шифрует данные своего репозитория, однако это не обещание шифрования всех метаданных Velero.
Используйте TLS, шифрование хранилища/диска, приватный бакет, узкие права и разделение операторов.

MinIO в стенде доступен через ClusterIP по HTTP; такой канал допустим только для локальной учебной сети.
Порты не публикуются наружу. Для облака используется HTTPS с проверкой сертификата.
Пароль репозитория устанавливается до первой копии, генерируется случайно и сохраняется в приватном work/.
Для восстановления после потери всего кластера этот пароль и S3-ключи нужно хранить отдельно от кластера.

**Рабочий стол этого компьютера находится в OneDrive.** Файлы work/ могут синхронизироваться средствами
ОС независимо от Git. Для реальных ключей переместите приватное состояние в каталог вне облачной
синхронизации и ограничьте ACL пользователя. `chmod` на Windows не заменяет настройку NTFS ACL.
В текущем стенде используются только сгенерированные локальные учебные ключи; VK Cloud ключи не создаются.

Node-agent требует привилегированного доступа к томам узла. Кластер выделен специально для практики.
MinIO находится в том же kind-кластере: удаление приложения переживает, удаление кластера/диска - нет.
Это проверка восстановления namespace, а не доказательство устойчивости к потере компьютера.

Нельзя вручную удалять объекты Kopia из бакета или применять lifecycle с меньшим сроком, чем TTL Velero.
Дедуплицированные блоки могут использоваться несколькими копиями. Используйте штатное удаление Velero
и обслуживание репозитория. Для Object Lock отдельно проверьте совместимость с очисткой и maintenance.
